  **rebutted because:** spec §3 binds the Export menu to core unchanged: "Loading, error and Retry, refresh, Customize, Save as, copy link, share, and the Export menu (CSV, Excel, PDF, email: p5-exports): core's report view, unchanged." Core's export, merged and approved in p5-exports, opens every group on purpose (`core/server/reports/export.go`: "A PDF keeps the reader's folds and sort; a CSV and an Excel file open every group."). The ambiguous sentence and the interim line labels (the customer's name until checkpoint 2's `detail.label`) go to the human under Design notes.
- **finding:** gate-2 critic, checkpoint 2, P1 (BLOCKING, all four `picker` shots): "the customers that have no parent are under a group header "(NONE)" with a whole-group pill "All (none) sub-customers". These customers are not sub-customers and have no parent name; the pill offers a pick with a label that has no meaning … The blank group is probably drawn by core's picker; if so, this is a core gap to report".
  **rebutted because:** spec §3 binds the grouping to core's mechanism: "sub-customers listed under their parent's name with a whole-group pick "All <parent> sub-customers": core `optionsFrom.group` and `groupLabel`". The spec does not ask for parentless customers to be ungrouped, so no spec line is broken; the odd label goes to the human under Design notes with the core option that would fix it.
- **finding:** reviewer B, checkpoint 2, DEFERRAL 1: "The document header names the Customer picks … Built: no header line … It stays a DEFERRAL until checkpoint 4 lands."
