# Report shell — checkpoint plan

Package: `books` (dir `books/`, branch `books/p5-report-shell`). Feature: `report-shell`. Spec: `docs/specs/report-shell-design.md` (approved, direction C). Ledger: `docs/plans/report-shell-ledger.md`. Paths below are relative to the package root; source lives in `tinycld/books/`. Package files import each other relatively (`../lib/x`), never with `~/tinycld/books/...`. Every screen runs on web and native. No raw hex: semantic Tailwind tokens, or `useThemeColor` for icon colors. No `console.*`. No `any`, no `biome-ignore`. Data goes through pbtsdb (`useStore`, `useLiveQuery` with `{ query, queryKey }`). This unit has no migration, no new collection or field, no endpoint, no Go change and no write of any kind. No core change: every control is an existing core component.

## Decisions that apply to every checkpoint

- **No seed change.** The fixture is not seeded. The e2e and the gate-2 captures read the ledger that `seed.ts` already posts: the accounts of the e2e book, the January and February entries of the current year, the register entries dated today and on the fiscal-year start, and the journal seed entries dated today. The e2e picks the "Today" preset (or a Custom date in 2000 for the empty states), so it has rows, or no rows, on any calendar date. The fixture stays the reference data and feeds the unit tests (`TRIAL_BALANCE_MODEL`, `PROFIT_AND_LOSS_MODEL`, `CUSTOM_NUMBER_FORMAT`, `HUB_ENTRIES`, `REPORT_ACCOUNTS`).
- **Dates** are ISO strings: a day is `YYYY-MM-DD`, a period (balance-row month) is `YYYY-MM`. Month arithmetic lives only in `lib/register-range.ts` (its helpers are exported in checkpoint 1) and `lib/report-period.ts`. `todayIso()` (from `lib/register-range.ts`) is the only clock read; tests pass `today` in. Quarters and fiscal years count from `books_settings.fiscal_year_start_month`, read through `fiscalStartMonth(settings)` (1 when unset or out of range).
- **Money** is integer cents end to end. Report figures are summed in whole cents by the report. The shell formats only through `formatReportAmount`, which divides and rounds once with `roundHalfAwayFromZero` from `lib/money.ts`. No screen does arithmetic on dollars.
- **Live queries** use `useLiveQuery({ query, queryKey })`. A disabled query returns `undefined` from `query`. Retry uses `recoverLiveQueries` from `@tinycld/core/lib/recover-live-queries` with only the queries that failed and only the collections those queries read; a source is cleaned only when its own status is `error` (tinycld #379), so a shared collection such as `books_access` may be passed as a source; a ready source keeps its rows and its other readers.
- **Options state.** The URL search params are the last valid options: `parseReportParams` turns them into `ReportOptions` on every render. The form (`useReportOptionsForm`, checkpoint 7) holds what the user is editing, including an invalid typed date. Change handlers validate the form (`handleSubmit`) and, when it is valid, write the URL with `router.setParams(serializeReportParams(...))`, which replaces the history entry. No `useEffect` writes the URL or syncs the form.
- **Surfaces.** One popover or sheet is open at a time: the period control, the Add filter menu, or one filter picker. `useReportUIStore` (checkpoint 3) holds which one, the Customize open flag and the folded section ids per report. A hub press calls `startVisit(reportId)`, which clears that report's folded ids and closes every surface and the Customize panel, so a new visit starts clean.
- **Picking a period preset closes the period popover** (it applied at once; the chip shows the resolved dates at rest). Editing a date keeps the popover open so the inline error stays visible.
- **Two stages on the report screen.** `ReportScreen` first waits for Books access and settings (`useReportPrerequisites`), because the presets resolve from the fiscal year start month. Meanwhile it shows the header and `LoadingState`, or the error alert with the settings retry. Then it mounts the body, which owns the form and calls the definition's `useReport`.
- **Definitions are mapped beside the registry.** `lib/report-registry.ts` holds only data (sections and entries with `available`), so `lib/shell-nav.ts` can compute the sidebar entry without importing any data hook. `lib/reports/definitions.ts` maps a report id to its `ReportDefinition` and returns it only while the registry entry is available. A later report unit flips its registry flag and adds its definition to that map.
- **Core pieces used:** `Popover` (`@tinycld/core/ui/popover`, `presentation` auto: a popover on tablet and wide, a bottom sheet on phone with `sheetSide="bottom"`), `Sheet` (`@tinycld/core/ui/sheet`), `Drawer`, `DrawerBackdrop`, `DrawerContent`, `DrawerHeader`, `DrawerBody`, `DrawerCloseButton` (`@tinycld/core/ui/drawer`), `Menu` (`@tinycld/core/ui/menu`), `Button`, `ButtonText` (`@tinycld/core/ui/button`), `DateField` (`@tinycld/core/ui/forms/fields/DateField`), `useForm`, `zodResolver`, `z`, `ButtonGroup`, `Toggle`, `SelectInput`, `useWatch` (`@tinycld/core/ui/form`; ButtonGroup, Toggle and SelectInput take `onValueChange`), `LoadingState` (`@tinycld/core/components/LoadingState`), `EmptyState` (`@tinycld/core/components/EmptyState`, the hub's empty state only, which has no action), `useBreakpoint`, `useWindowHeight`, `Breakpoint` (`@tinycld/core/components/workspace/useBreakpoint`; `desktop` is 1024 and wider, `tablet` 768 to 1023, `mobile` below), `useOrgHref` (`@tinycld/core/lib/org-routes`), `useThemeColor` (`@tinycld/core/lib/use-app-theme`), `log` (`@tinycld/core/lib/logger`), `create` (`@tinycld/core/lib/store`). Rows: `non-zero` keeps balance ≠ 0; `active` keeps an account with a non-zero balance or a posting in the period: for asset, liability and equity accounts a non-null `throughNet` or `edgeNet`; for income and expense accounts only fiscal-year activity (a non-null `edgeNet`, or `throughMonths` greater than `priorMonths`, null counted as 0), never activity before the fiscal year; `all` keeps every account (and the synthetic row when non-zero). Filter (when defined and non-empty): keep an account when its id is listed or `accountGroupOf` of a listed value equals its group. Cells: `debit` = balance when > 0 else null; `credit` = −balance when < 0 else null. Total: integer sums of the shown debit and credit cells (`kind: 'total'`, label "Total").
5. `useTrialBalanceRows(plan)`: `useStore('books_accounts', 'books_account_balances', 'books_journal_lines')` and ONE `useLiveQuery({ query: q => plan ? trialBalanceQuery({ accounts, balances, lines }, plan)(q) : undefined, queryKey: ['books.report.trial-balance', plan?.through, plan?.priorThrough, plan?.edge?.from, plan?.edge?.to] })` (the key carries the edge, so a plan with and without an edge are different queries). `useTrialBalance(options)`: `useBooksSettings()`; `plan` is `trialBalancePlan(options.period.to, fiscalStartMonth(settings))` once `options` and settings are ready, else null; `const result = useTrialBalanceRows(plan)`. `state`: `error` when `result.isError`, `ready` when `plan` is set and `result.isReady`, else `loading`. `model` is `buildTrialBalance({ rows: result.data, rowsChoice: options.rows, filter: options.filters.account })` only when ready. No second query and no `Map` stitching of separate query results. `retry`: `recoverLiveQueries({ queries: [result.collection], sources, onError: err => log.error('books.report', err) })`, where `sources` are the collections this one query reads (`books_accounts`, `books_account_balances`, and `books_journal_lines` only when `plan.edge` is set); core cleans only a source that is in error (tinycld PR #379), so a healthy source is never cleaned.
