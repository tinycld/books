## Design notes
1. Section row cells need a core change (phase 3 pass 2). The spec (§3 "The Reconciliation Report") puts Statement ending and Reconciled on on the section row. Core cannot draw that for a group that is `Open` with `Subtotals`: the engine gives the group row and its subtotal row the same cells (`core/server/reports/assemble.go` `groupWithLabel`), and the view shows no cell on an open group row that its subtotal row follows (`core/reports/lib/rows.ts` `rowCells`). With core as it is, the two values show on the row "Total 1000 Business Checking · reconciled by Ana Ruiz", not on the section row. The scratch route draws the spec's design with one step that core does not have (`withSectionCells` in `screens/helix-mockup.tsx`, marked DRAWN AHEAD OF CORE): an open group row keeps the cells of its `detail: "blank"` columns that are not sums, and its subtotal row leaves them out. The fixture's rows are as the engine sends them today. Decision for the plan: (a) a core checkpoint 0 with that rule (the standing rule is: a missing report capability is implemented in core first), or (b) no core change, the two values stay on the Total row, and the spec and the report reference change. The reference shows (a).
2. History table widths. The spec's minimums (130 · 180 · 120 · 120 · 190 · 150, 914 with the row padding) do not fit the 908 px that a 1280 px window leaves the list, and at 130 the header "Statement ending" with its sort arrow is cut. Measured widths in the reference: Statement ending 164 (fixed) · Account flex 2, minimum 166 · Ending balance 122 (fixed) · Cleared 112 (fixed) · Reconciled flex 1, minimum 178 · action 124 (fixed; link, 4 px gap, 44 px menu or a 44 px spacer). Table minimum 890. The table shows at 1280; at 1024 the list is cards.
3. History card. Line 3 with the count ("Reconciled Nov 21, 2026 by Ana Ruiz · 4 transactions") does not fit one line at 390 or 375. In the reference the count is on line 2, right, in `text-xs text-muted-foreground` (`shrink-0`; the account name takes the ellipsis), and line 3 is "Reconciled Nov 21, 2026 by Ana Ruiz".
4. Report widths. The report ships on core's `/a/reports/<id>` with no Books sidebar; the scratch route has the sidebar, so the rows are 324 px narrower than the window at 1024 and wider. Capture width → row width → shipping window: 1700 → 1376 → 1440; 1540 → 1216 → 1280; 1284 → 960 → 1024; 1028 → 704 → 768; 390 and 375 are the same on both.
5. Report display block (measured, in `lib/reconciliation-report-fixture.ts`): `oneLine.minWidth` 1360px (at 1216 one line leaves payee and memo 118 to 141 px and cuts "Bill payment 1041"); payee and memo `whiteSpace: normal`, `lineClamp: 2`; debit, credit, balance `minWidth: max-content`. Below 1360 the tablet arrangement (12 tracks, from 600 px): line 1 date 2 · transaction 4 · debit 2 · credit 2 · balance 2; line 2 payee 3 · memo 3 · statement 3 · reconciled 3. Phone arrangement (12 tracks; `layout=mobile` at 390 and at 375): line 1 date 4 · transaction 8; line 2 payee 7 · statement 5; line 3 memo 12; line 4 debit 4 · credit 4 · balance 4. A detail row keeps every line of an arrangement (`table-lines.ts` `rowLayout`), so the section columns cannot have a line of their own (it is an empty line in each cleared row); line 1 is the label's line (a cell there cuts the section label); three figures fill a phone line. So a phone does not show Reconciled on (the column is not in the phone arrangement; the section label names who reconciled). A shipping 1280 window shows the two-line tablet arrangement.
6. Column order in the reference: date · transaction · payee · memo · statement · reconciled · debit · credit · balance (the artboard's order; spec §4 lists statement and reconciled last). The Go spec must use this order to match the reference.
7. Core draws these, the reference keeps them: the subtotal label "Total 1000 Business Checking · reconciled by Ana Ruiz" is cut on tablet and phone rows (a label ends at the row's first figure); the row menu's "Undo reconciliation" is not red in the history (`RecordRowMenu` colors only `delete`) and is red in the finished summary's menu (core `Menu.Item isDestructive`): the plan picks one.
8. Fixture: eight finished reconciliations, not the spec's seven: the eighth is 1020 (the long account name) with no cleared transaction, which is also the report's `Fill` case. 1010 has October in progress (the blocked undo). The long person name is on 1010 September.
