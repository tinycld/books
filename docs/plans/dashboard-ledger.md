The phone shot reading the value the 1280 shot saved is the spec's own rule, "The switch is saved for the user and applies on every device." (spec §3), not a dependency to remove.
- **finding:** reviewer A, checkpoint 3, NOTE (capture.json:334-341): "`hidden-amounts-phone` waits for "•••••" and does not click `dashboard-hide-amounts`. It shows hidden amounts only because the shot before it saved the switch on. The page also draws "•••••" before the preference loads. The shot depends on the order of the shots.   **rebutted because:** a click there would turn the saved switch off, not on: the 1280 shot saved it on, and "The switch is saved for the user and applies on every device." (spec §3). The order is the manifest's documented rule, "The shots of one manifest run in file order on one database: a shot that writes changes what the shots after it see." (capture spec header). The shot waits for `dashboard-bank-banking` first and shows the switch on (reviewer A: "The shot that was taken does show the switch on"), so it is not the loading mask. Same basis as the checkpoint 2 rebuttal above.
- **finding:** critic, checkpoint 3, "For gate 3" 1: "read-only-1280: the report links ("A/R aging", "Expenses by vendor", "Profit and Loss report", "Sales by customer") show for the faked read-only user; the reference hides them for a reader.
