## Decisions that apply to every checkpoint

- **Slices.** Checkpoint 1: the tabs, the Files tab, the three lists (no toolbar, newest first), their loading/error/empty states, the counts, the compact phone strip, "Review transactions" on the import result, and the seeded import. Checkpoint 2: the toolbar (search, Dates, Type, Clear filters), the date order toggle and the filtered empty state. Checkpoint 3: the detail drawer and Exclude / Move to For review of one transaction from it, with the update rule, the Go rule tests and the audit. Checkpoint 4: choosing rows, the selection bar, the batch buttons, refusals and the read-only checks. Checkpoint 5: the keys and the help topic.
- **Seed (a deviation from spec §4 "uploads one more CSV file").** The seed uploads an **OFX** file, `checking-2026-10.ofx`, to 1000 Business Checking and imports every line of it as superuser. Reason: only the OFX parser fills `memo` and `check_number` (`server/bank_ofx.go`; the CSV mapping has no memo or check column), so a CSV seed could not show a row's second line or the drawer's Memo and Check no. fields in the e2e book and the help screenshots. Four of its rows are then set to `excluded`. The file has no `<LEDGERBAL>`, so 1000's card shows no statement line (as today). The seeded `checking-2026-09.csv` stays `uploaded`.
- **E2E accounts.** Every e2e test that writes creates its own number-less Bank account and imports its own OFX file through the UI (`importReviewStatement`, checkpoint 1), as `bank-import-mapping.spec.ts` does, because `banking-page.spec.ts` and `banking-keys.spec.ts` read 1000 Business Checking and the shared DB runs spec files on two workers. An imported connection cannot be disconnected; it sorts last in the strip. Tests that only read (read-only, load error) use the seeded 1000 Business Checking and 2100 Company Card and never write. Every file has unique bytes: the test's stamp in every name and memo (lessons 2, 3, 15). OFX is used, not CSV, because only OFX carries a memo and a check number.
- **Order.** Newest first: `date` desc, then `line` asc, then `id` asc. Oldest first: `date` asc, `line` asc, `id` asc (file order inside one day in both). Reviewed and Excluded (paged): `date` in the chosen direction, then `id` asc, both `stringSort: 'lexical'` (TanStack DB builds a page cursor only for a lexical order, lib/list-search.ts).
