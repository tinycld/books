## Design notes
- cp 3 · map-1280 / choose-1280 (critic NOTE ×2): no visible focus ring on the autofocused header select / select-all box — Chrome draws `:focus-visible` on a script focus only after a keyboard interaction, and the capture reaches the page by a click; e2e test 8 asserts both focuses directly.
- cp 3 · reviewer A #3: `i` stays offered while an upload runs (only `u` is withheld on busy); pressing it mid-upload opens an older waiting file's import while the upload continues in its store. The spec's "the same `offered` rule as `n` and `u`" names write access and writes available, not busy.
- cp 3 · reviewer A #5: `useFocusOnOpen` keyed on `[isEnabled]`, so a phone→wide resize on Choose transactions moves focus to the select-all box at that moment; the Map step's `autoFocus` fires only at first mount.
- cp 2 · CLOSED IN CP 3 (carry-over fixed, `SampleTable` inner `View` `flex: 1`; confirmed in cp3 map-1280 shots) · OPEN AT ROUND CAP (critic BLOCKING, rounds 1 and 2: `evidence/cp2/critique-fix.md`, `critique-fix-2.md`) · map*-1280 and map*-390: "Your file" sample table — the file columns are ~173 wide, so a 3-column file (56 + 3×173 ≈ 575) overflows the 478 box at 1280: COLUMN 3 is cut and the table scrolls, though 56 + 3×120 = 416 fits; on a phone fewer columns show before scrolling. Sequence: reviewer B #3 (fixed 120 width → "at least 120") → fix 3 gave the cells `{ minWidth: 120, flexBasis: 120, flexGrow: 1 }` with the content container still sized by its content → critic BLOCKING (overflow) → fix round 2 set `contentContainerStyle={{ width: '100%', minWidth }}` → critic BLOCKING (unchanged). Root cause found by the runner: the inner table `View` in `SampleTable.tsx` has `style={{ flexGrow: 1 }}` with flex-basis auto and no shrink, so it takes the cells' text width (max-content) and overflows the box-wide container. Fix: give it `flex: 1` (or `width: '100%'`), so the cells share the container. Before fix 3 the table had an empty strip on the right instead (columns fixed at 120).
- cp 2 · reviewer A #2: the prefill query `from(imports).innerJoin(files)` has no `where` on the imports side; TanStack DB picks the driving side by store size, so when imports drives it loads and subscribes to the whole `books_bank_imports` collection (each row carries its `lines` array). No wrong data (the first mapping is fixed at mount). The plan prescribed the query (Do 3); a fix drives from `files where connection, format = csv` or narrows imports with a subquery on that connection's csv file ids.
- cp 2 · reviewer A #4: header "Debit Amount, Credit Amount" guesses `one` with Amount = the debit column (containment match on "amount"), though money in and money out also match. Follows the plan's Produces rule ("'one' when Amount is found"); the person checks every guess. A change (prefer `two` when Amount matched only by containment and both money columns matched) is a spec decision.
