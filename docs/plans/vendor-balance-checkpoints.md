- **D16 — the core fix of checkpoint 3's stop (human, 2026-11-20).** Checkpoint 3 stopped on the bar "no step is a `SCAN` of a large table": every run's `MATERIALIZE w` had `SCAN books_journal_lines`. The verified cause (lane staging file `cp3-options.md`): core reads a Select field as `NULLIF(<column>, '')` (`fieldSQL`, `core/server/reports/stmt.go` lines 262 to 271) and writes `eq` as `IS` (`core/server/reports/formula.go` line 859). SQLite cannot use `idx_books_accounts_type` through `NULLIF`, so it does not know that `account.type = accounts_payable` is selective and keeps the lines as the outer loop. `IS`, the `LEFT JOIN` and `posted IS true` are not the cause: a required (inner) hop keeps the scan, and so does `NULLIF(type, '') = …`. Probed on dataset S, run 1, with no statistics and after `ANALYZE`: the compiled term **and** the bare column test, `(NULLIF(c, '') IS 'x' AND c = 'x')`, gives `SEARCH books_accounts USING INDEX idx_books_accounts_type (type=?)` and then `SEARCH books_journal_lines USING INDEX idx_books_jlines_account_date (account=?)`. Runs 2 to 7 were not probed (the same filter), and no time was taken. The two forms give the same value for every stored value: NULL (no linked row, or a row the reader cannot see) gives `0 AND NULL` = 0; `''` gives 0 and 0; any other value gives the same answer two times. So the result is the same in a filter, in a formula and under `not`.

**Spec:**
- §2: "A shipped report `books.vendor_balance`, title **Vendor Balance** (Q6), description "What you owe each vendor on one day, from posted transactions on Accounts payable accounts." It opens in core's report view (`/a/reports/<id>`) and is listed in the Books Reports hub (`/a/reports?package=books`). Like every `books.*` shipped report it is `Unpublished` and shared with every Books reader by `server/report_shares.go` (its filter `shipped_key ~ 'books.%'` covers the new key)."
- **What counts (Q2).** The report reads the posted journal lines on accounts of type `accounts_payable`, dated on or before the As of day. A vendor's balance is its lines' credits minus debits. It is the Open balance of the vendor's page (`books_party_balances`) on the same day, the vendor's Total in the A/P Aging for that day, and the report's Total is the Accounts payable figure of the Balance Sheet for that day. A draft or void document has no posted line, so it does not count; a void's reversal lines cancel the original.
- **Sign (Q2).** A figure is positive when the business owes it. A vendor that owes the business (an unapplied vendor credit) has a negative figure; the Total nets it.
- **Rows.** One level: the vendor. Vendors have no parent, so there is no family row and no subtotal row. The report ends in one Total row.
- **Columns.** **Vendor** (the label) and **Balance**. On a vendor row and on the Total, Balance is the sum of credits minus debits.
- **No vendor (Q4).** Accounts payable lines that name no vendor (an opening balance, a journal entry with no name) form one row "No vendor", after every vendor under both Order choices. It opens into its lines like a vendor row. With vendors picked in the filter it does not show.
- **Params.**
  - **As of** (core `asOf`), default **Today**.
  - **Rows** (choice, Q5): **Non-zero** (default) shows a vendor whose balance is not 0; **With activity** also shows a vendor with posted lines that add up to 0. Core `groups[].having` on the vendor level.
  - **Vendor** (Books `vendorsParam()`: multiple, every vendor by name, inactive ones included). Unset = every vendor and the No vendor row. The document header prints "Vendor: …" for the picks.
  - **Order** (choice): **Name** (default; by name, ignoring case) or **Largest balance** (by Balance, largest first).
- **Inactive vendors.** An inactive vendor with a balance (or, under With activity, with lines) shows; its row is muted (core `groups[].muted`) and its label ends with " (inactive)" (Books `vendorGroup()`), as in the A/P Aging.
- **Heading.** The Books business name, "Vendor Balance", "As of <day>" (core `ReportDocumentHeader`, `Source.Heading`).
- **Empty.** A book with no posted Accounts payable line on or before the day shows core's empty report text for the day (`emptyMessage`) and no rows.

   ```go
   package reports

   // storedSelect is the stored column (col) a Select field is read from as
   // sql; a copy of the expr whose sql changed no longer reads it.
   type storedSelect struct{ col, sql string }

   // selectEq is eq of a Select field with a text literal that is one of its
   // option values, with the same test on the stored column:
   // (NULLIF(c, '') IS {:p} AND c = {:p}). A Select reads as NULLIF(c, ''),
   // which no index on c serves, so SQLite cannot tell that the condition is
   // selective and scans the rows it could search. The second term is one a
   // plain index on c serves. It never changes the value: a NULL c (no linked
   // row, or one the reader cannot see) gives 0 AND NULL, which is 0; a blank
   // c gives 0 and 0; any other c gives the same answer two times. Both terms
   // bind the value; no value is ever written into the SQL text. "" when
   // neither side is such a pair, and eq is written as before.
   func selectEq(args []expr) string {
       for i, a := range args[:2] {
           v := args[1-i]
           if a.sel.col == "" || a.sel.sql != a.sql || v.text == nil || !storedOption(a.options, *v.text) {
               continue
           }
           return "(" + a.sql + " IS " + v.sql + " AND " + a.sel.col + " = " + v.sql + ")"
       }
       return ""
   }

   // storedOption is true for a text that is one of a Select's option values.
   func storedOption(options []Option, text string) bool {
       return slices.ContainsFunc(options, func(o Option) bool { return o.Value == text })
   }
   ```
