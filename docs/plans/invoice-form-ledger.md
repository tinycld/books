## Design notes
- cp 0 · reviewer A NOTE 5: core `TableField` draws a row with a missing or unknown `kind` as the first kind, but the schema refuses it at `lines.N.kind`, where no cell shows the error; only a host bug (e.g. a `replaceRow` row without `kind`) reaches it, and the save then fails with no visible reason.
- cp 0 · reviewer A NOTE 6: a second row key pressed before the rAF focus move lands targets the removed row and does nothing (the key is lost, nothing breaks).
- cp 0 · reviewer A NOTE 7: spec E1 "the Go mirror validates the kind and its cells" — core Go checks the host declaration only (Go accepts `rowKinds: []`, which TS refuses; no `columnAt` check). Core never sees host-table rows: Books checkpoint 2 validates each line's kind and cells ("Line %d: A %s line has no product or amount").
- cp 0 · reviewer A NOTE 8: a locked built-in already stored as hidden shows Hidden on and disabled in the builder, and the server refuses every save of that definition (same as required built-ins today; not live).
- cp 0 · reviewer A NOTE 9: on native, after the last line is removed, the screen-reader focus event goes to the wrapper `View` of the first add action, not the button; VoiceOver may not land on "Add line".
- cp 0 · fix review r1 NOTE 1: Option-key matching by `event.code` uses US positions; on AZERTY `Alt+a` and `Alt+q` could both match one press if both were registered (no such pair is).
- cp 0 · fix review r1 NOTE 4 → **Books checkpoint 4**: every Books line host cell (`tinycld/books/forms/product-fields.tsx` and the other line cells) must call `noteFocus` / `noteBlur` from `TableCellContext`, or the row keys do not see a focused host cell on native.
- cp 0 · fix review r2 NOTE: a cell with two focusable elements (date input + calendar button, select options) has one cell key; on iOS Full Keyboard Access, a focus-before-blur order between them clears `focused` and the row keys do nothing until the next cell focus (fix: a focus depth count per cell).
- cp 0 · fix review r2 NOTE: RN `Switch` on iOS may not send `onFocus` / `onBlur`; the toggle cell then behaves as before (no focus noted).
