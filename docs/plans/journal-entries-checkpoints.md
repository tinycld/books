# Journal entries — checkpoint plan

Package: `books` (dir `books/`). Feature: `journal-entries`. Spec: `docs/specs/journal-entries-design.md`. Paths below are relative to the package root. Source lives in `tinycld/books/`. Package files import each other relatively (`../lib/x`), never with `~/tinycld/books/...`. Every screen works on web and native. No raw hex: semantic Tailwind tokens or `useThemeColor` (a test checks every colour utility against `global.css`). No `console.*`. Data goes through pbtsdb (`useStore`, `useLiveQuery`, `useRecord`), writes through `useMutation` generators from `@tinycld/core/lib/mutations`. This unit has no migration, no new collection, no custom endpoint, no Go change and no core change. Row types derive from the query result; no hand-declared row interface. No `useState` + `useEffect` sync. Forms use zod through `zodResolver` and `useForm` from `@tinycld/core/ui/form`.

Reference screenshots live in `docs/plans/journal-entries-reference/` as `<shot>-<width>-<scheme>.png` (shots `list`, `list-empty`, `list-no-match`, `new`, `new-unbalanced`, `new-lines`, `new-unbalanced-lines`, `posted`, `void`, `reverse`; widths 390 and 1280; schemes light and dark). `lib/journal-entries-fixture.ts` holds the data they show. The scratch route `tinycld/books/screens/helix-mockup.tsx` is a structure aid only; it is git-excluded and deleted at the end, so no checkpoint imports from it. Build from the screenshots and the fixture.

Review mode: C (unattended).

## Decisions that apply to every checkpoint

- **Line limit.** The client refuses more than 200 lines (`maxLines`) with a zod message shown in `FormErrorSummary`; the spec's "refused by the server" is the server's own cap (1000 in `server/posting.go`), which is wider, so the client rule is the one a person meets. `entry-add-line` stays enabled; the 201st line makes Save draft and Post show "An entry can have at most 200 lines.".
- **Money is integer cents.** Display through `formatMoney` / `amountText` (`lib/money.ts`), input through `parseMoney`, sums through `lib/entry-lines.ts`. No arithmetic on dollars.
- **Dates are ISO text** (`YYYY-MM-DD`). Dates are compared as strings. Only `lib/register-range.ts` does calendar arithmetic; entry code reuses `todayIso`, `rangeForPreset`, `formatDay` from it.
- **Amount, date and memo cells.** Core `TextInput` and `TextAreaInput` cannot share a column width on web (the input keeps its intrinsic width and overflows the cell). The Debit, Credit and line-Memo cells bind core `PlainInput` (`@tinycld/core/ui/PlainInput`) through `useController` (`minWidth: 0`, `width: '100%'`). The header Date and Memo fields use core `TextInput` / `TextAreaInput` (they are not in a shared column). Date is a `TextInput` with a zod `YYYY-MM-DD` rule (core `DateField` is not used; no core change).
- **Account picker** is core `SelectInput` with options "number name", sub-accounts indented, active accounts only, chart order. The line `account` field keeps the id.
- **Cell style constants.** The line table and the list table each export one set of cell style constants (`ENTRY_COLUMNS`, `LINE_COLUMNS`) shared by the heading row and every row. Debit, Credit and Total never shrink and are right aligned. A column never collapses to blank (`minWidth`, ellipsis).
- **Layout.** Headers, the totals strip and the action bar sit outside the scroll area. Horizontal `ScrollView` content uses `contentContainerStyle={{ width: '100%', minWidth }}`. Rows and tap targets are 44pt minimum.
- **Test ids** (all later checkpoints use these exact names): list `entries-screen`, `entries-title`, `entries-new`, `entries-search`, `entries-chip-all|draft|posted|void`, `entries-range`, `entries-table`, `entries-row-<id>`, `entries-card-<id>`, `entries-cell-<column>-<id>` (column one of `date`, `number`, `type`, `memo`, `status`, `total`), `entries-empty`, `entries-no-match`, `entries-clear-filters`, `entries-error`, `entries-retry`, `entries-loading`, `entries-row-menu-<id>`; entry `entry-screen`, `entry-back`, `entry-title`, `entry-badge`, `entry-big-total`, `entry-date`, `entry-number`, `entry-memo`, `entry-auto-reverse`, `entry-line-<i>`, `entry-line-account-<i>`, `entry-line-debit-<i>`, `entry-line-credit-<i>`, `entry-line-memo-<i>`, `entry-line-menu-<i>`, `entry-add-line`, `entry-totals`, `entry-total-debits`, `entry-total-credits`, `entry-balance-status`, `entry-actions`, `entry-cancel`, `entry-save-draft`, `entry-post`, `entry-post-new`, `entry-more`, `entry-error-summary`, `entry-line-error-<i>`, `entry-read-only`, `entry-detail-<field>`, `entry-link-reverses`, `entry-link-reversed-by`, `entry-link-replaces`, `entry-not-found`, `entry-no-access`, `entry-header-more`, `entry-edit`, `register-drawer-open-entry`, `entries-menu-open|edit|reverse|void|delete`; dialogs `reverse-dialog`, `reverse-date`, `reverse-memo`, `reverse-confirm`, `void-dialog`, `void-confirm`, `delete-draft-dialog`, `delete-draft-confirm`, `discard-dialog`, `discard-confirm`.
- **E2E rules.** Specs use `login`, `navigateToPackage`, `clickSidebarItem` from `@tinycld/core/e2e-helpers`; never `page.goto` after login; never raw PocketBase writes. Entries are created by driving the form (`createPostedEntry` in `tests/e2e/journal-entries-helpers.ts`, checkpoint 5). Every spec runs at desktop (`DESKTOP`, 1280x800) and at phone (`PHONE`, 390x844): `navigateToPackage` at the default viewport first, then `page.setViewportSize(...)`, as in `tests/e2e/account-register-states.spec.ts`. Each `test.describe` title starts with `journal-entries:`. The seed has no read-only Books member, so no spec can log in as one: read-only gating is covered by `entryActions` and `newEntryVisible`-style pure tests (checkpoint 1) and each spec header says so. Every e2e that creates data uses a memo made unique with `Date.now()` so reruns do not collide.
- **Seed memos** (checkpoint 1, `ENTRIES_SEED` exported from `lib/journal-entries-fixture.ts`): `draft` "Entries seed draft", `posted` "Entries seed posted", `reversed` "Entries seed reversed", `voided` "Entries seed voided", `auto` "Entries seed auto reverse". All are dated today so they fall in This fiscal year on any date.
