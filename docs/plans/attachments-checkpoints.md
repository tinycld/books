**Spec alignments made in phase 4** (ledger Phase notes; no Behavior bullet changes meaning):
- **The save step is in `useDocumentSave`, not `useRecordSave`.** Bills and expenses save through the document layer's `hooks/useDocumentSave.ts`; `useRecordSave` saves single-record screens. The quoted bullets keep the spec's words; checkpoint 4 builds the step in `useDocumentSave`.
- **Thumb size.** Core `Thumbnail` requests `${size}x${size}`, so a 40 px thumbnail asks PocketBase for `40x40`. The migration declares `thumbs: ['40x40']` (not `80x80`): PocketBase serves the original file for a thumb size the field does not declare, so without it every 40 px box would load the full-size image.
- **Example name.** The spec's example "Ana Lopez" is the fixture's `Ana Ruiz`; tests use the fixture name.
- **The server checks size and type first.** Core `uploadRecordWithFile` keeps only a response's top-level message, so a PocketBase schema error (maxSize, mimeTypes) would reach the person as "Failed to create record." The create-request hook (checkpoint 1) refuses an over-size file and a type off the allow-list with the spec's client texts before PocketBase's own validation, as `stampBankUpload` does; the schema's `maxSize` and `mimeTypes` stay as the last check.
- **One attachment query per document.** Spec §4 puts `field = ''` in the section's `where`; the client's 25-file count also needs the custom File field rows, so `useDocumentAttachments` (checkpoint 2) reads every row of the document and splits them in the hook.

## Decisions that apply to every checkpoint

- **The kind.** Every attachments API (helpers, hooks, components, the save step) takes the `SalesDocumentKind` (`BILL_KIND`, `EXPENSE_KIND`) and reads `kind.testId`, `kind.noun` (`'Bill'`, `'Expense'`), `kind.shortcutGroup` and `kind.features`. Where this plan writes `kind.doc.testId`, `kind.doc.noun` or `kind.doc.shortcutGroup`, use the `SalesDocumentKind` field of that name (in `useDocumentSave` the kind is `state.kind`). Text helpers take `kind.noun` in title case and lower-case it where the sentence needs it; tests pass `'Bill'` / `'Expense'`.
- **The date on a stored row** is `new Date(created).toLocaleDateString('en-US', { month: 'short', day: 'numeric', timeZone: 'UTC' })` (`Nov 14`, no year), in `lib/attachments.ts`; `uploadedOnText` is not used (it gives `Nov 14, 2026 by …`).
- **Test files.** The server sniffs each upload's type, so every e2e file has real bytes: `testFile(name, size?)` in `tests/e2e/attachments-helpers.ts` builds a `.pdf`, `.png` or `.jpg` from `ATTACHMENT_SEED_FILES` padded with zero bytes to `size` (trailing bytes do not change the sniffed type), and a `.txt` / `.csv` from plain ASCII. No e2e uploads an `.xlsx`; where a test needs another accepted type it uses `notes.csv`.
- **The remove dialog.** `ConfirmDialog` `title` `Remove <name>?`, `message` `It is deleted from this bill.` / `It is deleted from this expense.`; `removeMessage(name, noun)` returns `{ title, message }`; the e2e reads both.
