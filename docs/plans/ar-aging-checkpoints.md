- **D18 — checkpoint 5, the core rule filter that reads no row (human, 2026-11-18, "option 1").** Checkpoint 3 stopped on the bar "No step is `SCAN books_journal_lines` or `SCAN books_journal_entries`" (runs 6 and 7). Cause: core's `ruleSelect` (`core/server/reports/rules.go`) writes a list rule that joins as `+id IN (SELECT id FROM (SELECT DISTINCT t.* FROM t <joins> WHERE <rule>))`. When the rule names no column of the collection's own row (the Books read rule: the reader and `@collection.books_access` only), the id list is every row of the collection, so SQLite reads the whole table one time for each read of the rule CTE. The human approved: when every name the rule resolver resolves starts with `@request.` or `@collection.`, core writes the rule as a filter that reads no row of the collection, with no `DISTINCT` and no id list, so a link to the collection stays a search by its primary key.
  - *The form.* `SELECT t.* FROM t WHERE EXISTS (SELECT (1) FROM (SELECT 1) __rule <the resolver's joins> WHERE <the rule's expression>)`. It gives the same rows as the `DISTINCT` form for any rule: a row is kept when one combination of the joined rows meets the expression, and `EXISTS` keeps each row one time. `__rule` is a one-row table that stands where the collection stood, so the joins (`LEFT JOIN users __auth_users ON …`, `LEFT JOIN <collection> __collection_…`) keep their text.
  - *Detection.* A wrapper around the resolver of `core.NewRecordFieldResolver` records each name of a successful `Resolve` (no error and an `Identifier` that is not empty). PocketBase's filter builder calls `Resolve` for every identifier token, one name at a time (`third_party/pocketbase/tools/search/filter.go`, `resolveToken`), so `@collection.x.f ?= col` records `col` by itself. It also calls `Resolve` for `true`, `false` and `null`, which the record resolver refuses (the builder then takes its own constant): a refused name is not recorded, or the Books rule (`… can_read ?= true`) would never take the new form. The interface is `search.FieldResolver` (`UpdateQuery(*dbx.SelectQuery) error`, `Resolve(string) (*search.ResolverResult, error)`, `third_party/pocketbase/tools/search/simple_field_resolver.go`), on core's pinned PocketBase (`core/server/go.mod`: v0.40.4, replaced by `third_party/pocketbase`); no fork file changes. `ruleSelect` passes `allowHiddenFields` true, so the resolver builds no nested list rule with an inner resolver that the wrapper would not see (`record_field_resolver.go`, `updateQueryWithCollectionListRule` returns at once).
  - *Which rules take it.* A rule whose recorded names all start with `@request.` or `@collection.` **and** that joined (the built query is `DISTINCT`). A rule that reads no row and joins nothing (`@request.auth.id != ""`) is already a plain condition in place and does not change. A rule that names a column of its row, a relation path or a back-relation keeps the id-list form when it joins, and the in-place form when it does not: no change.
  - *A comparison of an `@collection` field with no `?`* (`@collection.x.user = @request.auth.id`, "every joined row") makes PocketBase add a multi-match subquery that reads the row's id (`__mm_<t>.id = t.id`, `tools/search/multi_match_subquery.go`). Its names are still only `@collection.` and `@request.`, so it takes the new form; the subquery reads the outer row inside the `EXISTS`, the rows stay right, and SQLite runs the `EXISTS` for each row it reads. The id-list form reads the whole table for such a rule, so the new form is never the slower one.
  - *A detection error cannot change rows.* The `EXISTS` form is right also for a rule that reads its row (the subquery then reads the outer row). One shape is known to pass the detection and read its row: `@request.body.<field>:changed`, which PocketBase builds with its inner resolver (`record_field_resolver_runner.go`, `processRequestBodyChangedModifier`), so the wrapper does not see the row's column. A report's list request has no body; the rows stay right; the only cost is a filter run for each row. The comment of `readsNoRow` says so.
  - *Probed in phase 4* (2026-11-18, a `go test -overlay` copy of `rules.go` in the lane scratchpad; no repo file changed): the SQL of the forms above for `zoo_sites`, `zoo_ledger_entries` (`withBalanceZoo`), a multi-match rule, `zoo_animals`, `zoo_feedings` and `zoo_keepers`; the rows equal the list API for each; the plan of `WITH r AS (<rule>) SELECT number FROM r WHERE id = ?` is `SEARCH zoo_ledger_entries USING INDEX sqlite_autoindex_zoo_ledger_entries_1 (id=?)` and a `SCALAR SUBQUERY` (run one time) with no scan of the collection; and with the same overlay Books `go test -run 'TestARAging(QueryPlans|RunsAgree|NoAccess|Ties)' .` passes on checkpoint 3's tree (the 8 failures of the stop are gone).

   ```go
   // ruleNames is PocketBase's rule resolver, recording each name of the rule
   // that it resolves. The filter builder asks it for every identifier of the
   // rule, one at a time, so "@collection.x.f ?= col" records col by itself. It
   // also asks for true, false and null, which the resolver refuses (the
   // builder then uses its own constant): a refused name is not a name of the
   // row and is not recorded.
   type ruleNames struct {
       *core.RecordFieldResolver
       names []string
   }

   func (r *ruleNames) Resolve(field string) (*search.ResolverResult, error) {
       res, err := r.RecordFieldResolver.Resolve(field)
       if err == nil && res != nil && res.Identifier != "" {
           r.names = append(r.names, field)
       }
       return res, err
   }

   // readsNoRow reports whether the rule names only the request and other
   // collections: no column of the collection's own row, no relation path and
   // no back-relation. Such a rule gives one answer for every row. Two shapes
   // pass and still read the row: a comparison with every joined row (no "?")
   // reads its id, and "@request.body.x:changed" is built by PocketBase's own
   // inner resolver. Their rows stay right, because the EXISTS form may read
   // the outer row; it is then run for each row.
   func (r *ruleNames) readsNoRow() bool {
       for _, name := range r.names {
           if !strings.HasPrefix(name, "@request.") && !strings.HasPrefix(name, "@collection.") {
               return false
           }
       }
       return true
   }
   ```
