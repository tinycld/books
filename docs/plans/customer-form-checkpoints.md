- **Two core form hooks, one adapter.** `useCustomerForm` calls `useFormCreate` and `useFormEdit` on every render (hooks cannot be conditional; a route's mode never changes for its life) and returns the one that matches the target. The other one is idle.
- **Host components bind with a local form.** Core host components get only `value` and `onChange` (`BuiltinFieldProps`), and core `TextInput` and `Toggle` need a react-hook-form `control`. `components/forms/use-host-value-form.ts` gives `ContactInput` and `AddressField` a local `useForm` whose `values` come from the host value; each input's `onValueChange` sends the whole value back through `onChange`. The local form validates with zod through `zodResolver` (`@tinycld/core/ui/form`, `mode: 'onChange'`), with schemas in `lib/host-value-schemas.ts` that mirror the value shape the server checks: strings, phone and mobile at most 40 characters, each address part at most 200. Email and URL format, the parent rules and duplicate names stay server rules (spec Form); local errors do not block the outer save, so the server stays the authority. `ContactInput` hides its local error (the core cell draws the field's one error; `maxLength` on the input stops typing past the limit), and an `AddressField` part input shows its own length error under that part, which the cell (one error for the whole address) cannot place. This local form is what makes the checkpoint 0 `min-w-0` fix load-bearing.
- **Error display.** Field refusals land on their fields through the host's `onError` (core `formErrorHandler`). A refusal with no field (`messageOnlyRefusal` from `lib/refusal.ts`) becomes `form.setError('root', …)`. `CustomerChild` passes `summary="root"` to core `FormRenderer` (the checkpoint 0 option) in both create and edit: the renderer's `FormErrorSummary` (`form-error-summary`) then lists only the root error and shows whenever one exists, so an edit save (`patch()`, which never marks the form submitted) shows it too, and field errors render inline only.
- **Leave guard input.** `useLeaveGuard(isDirty && !isSaving)`: `isSaving` is the save mutation's `isPending`, which is true from the render after `mutate()` until after `onSuccess`, so `leave()` from `onSuccess` is never held (core `usePreventRemove` reads the value of the last render). A record deleted elsewhere unmounts `CustomerChild` (the route renders `CustomerNotFound`), which removes the guard. A delete from the row menu of the open customer does not: `useCustomerFormStore.deleting` (checkpoint 7) is set synchronously before the delete mutation runs; while it names the open customer, `[id].tsx` keeps rendering `CustomerChild` with the record snapshot the flag holds (no not-found flash), and `CustomerChild` passes `isDirty && !isSaving && !isBeingDeleted` to the guard, so `leave()` from the delete's `onSuccess` is not held.
