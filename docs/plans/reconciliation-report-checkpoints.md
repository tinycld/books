**Rules for the code**

- Row types come from the query result (`type Row = NonNullable<typeof rows>[number]`); no hand-written row interface. Pure helpers take `Pick<…>` of the generated types `BooksReconciliations` and `BooksAccounts`.
- Reads are `useLiveQuery` with `{ query, queryKey }`; a load error is detected on its query and Retry calls `recoverLiveQueries` once over every failed query through `mergeRecoveries` (`lib/live-recovery.ts`). In e2e a load error is made with `route.fulfill({ status: 400 })` (pbtsdb reports an error only for a 4xx), and the route is removed with `page.unrouteAll({ behavior: 'wait' })` before Retry.
- Writes are `useMutation` from `@tinycld/core/lib/mutations` with a pbtsdb `update`. A screen that must stay through a write sets a synchronous Zustand flag before the mutation starts and clears it in `onSettled`.
- Keys: the screen takes the `list` scope with `useShortcutScope('list')` and registers its keys with `useRegisterShortcuts` (`tinycld/core/lib/shortcuts/use-register.ts`), each only while its action is offered; a button with a key is a core `ShortcutButton` with `scopeOwner`. An open core `Dialog` pushes its own scope (`tinycld/core/ui/dialog/index.tsx`), so no list key fires under it. A core `Menu` pushes no scope: each list key has `when: noMenuLayerOpen`, the local function of `hooks/useReconcileAccounts.ts` (line 44; read which core layer stack it asks). The history hook uses the same function: checkpoint 3 exports it from `hooks/useReconcileAccounts.ts` (one definition). The pattern to copy is `hooks/useReconcileAccounts.ts` (keys, focus, `rowFocusStyle` of `tinycld/core/components/focusable-row.ts`).
- On a phone core `Dialog` is a sheet with no dialog role: e2e finds it by test id.
- A server refusal text is written without its final period where PocketBase adds one (read `refuse`, `refuseNamed`, `refuseField` in `server/errors.go` first). E2E asserts the text the screen shows.
- Light and dark: semantic classes and `useThemeColor` only. JSX stays small: state, handlers and derived values are in the hooks named in each checkpoint.
- Logging: `log.warn('books.reconcile', …)` on the client; `logging.ForPackage("books")` on the server.
- Test ids, widths, row heights and texts are those of the scratch route `tinycld/books/screens/helix-mockup.tsx`. No built file imports the scratch route.
- E2E helpers that exist: `login`, `navigateToPackage`, `clickSidebarItem` (core); `daysAgo`, `openReconcile`, `createReconcileAccount`, `postDatedEntry`, `startReconciliation`, `openWorkScreen`, `lineRow`, `pressRow`, `finishReconciliation`, `reconciliationIdOf`, `accountIdOf`, `accountRow` (`tests/e2e/reconcile-helpers.ts`); `uniqueName` (`tests/e2e/record-form-helpers.ts`); `visibleScreen` (`tests/e2e/screen-helpers.ts`); `fakeReadOnlyAccess` (`tests/e2e/banking-helpers.ts`, installed before `login`); `exportReport` (`tests/e2e/books-report-helpers.ts`).
