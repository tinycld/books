## Plan decisions (where the plan settles what the spec or phase 3 left open)

- **D1 — a zero amount draws "$0.00".** `amountText` (`lib/money.ts`) gives `''` for zero, which is right in a table column and wrong for a figure that leads a card ("Unpaid" with no text reads as missing data; reference shot `long` shows "$0.00"; the Chart of Accounts does the same with `balanceText`). One helper, `dashboardAmount(cents, currency, hideAmounts)`, draws every dashboard amount: the mask when amounts are hidden; else `amountText(cents, currency)` (a negative amount keeps the hyphen sign `formatMoney` writes, `lib/money.ts` lines 68–69; not `MINUS`, which marks an amount shown as taken off); else, when that text is empty (zero), `formatMoney(0, currency)`. An amount Books cannot hold exactly (`ownBalance` gives `null`) draws `TOO_LARGE_TEXT` (`lib/money.ts`) in the danger tone, as `balanceText` does. Spec §3 "The page", fourth bullet, says so (edited in phase 4).
- **D2 — the preference hook uses core `useUserPreference`, extended in core (amended 2026-11-22, human: core first).** Core `useUserPreference` returned only the value and a setter, and spec §3 needs a load state, a load error with Retry, and the toast "The dashboard change was not saved.". A core task on core branch books/p5-dashboard (commit 5cb8a8dd; it merges at the next design gate, before the Books PR) added a third tuple element `{ isReady, isError, retry }` and an option `{ onSaveError }`. `hooks/useDashboardPrefs.ts` wraps it (checkpoint 2 step 4). This matches spec §4.
- **D3 — the empty text is the spec's rule.** "No sales in last 6 months.", "No expenses in this fiscal year.", "Nothing posted in last month.": the period label in lower case (`periodLabel.toLowerCase()`), with no article.
- **D4 — the mask keeps the figure's size.** With Hide amounts on, the mask text replaces the amount text in the same element, so the leading figure is "•••••" at `text-3xl` (shot `hidden-amounts-*`).
- **D5 — columns follow the page's own width.** The spec's breakpoints stand (three columns from 1100 px of page width, two from 700 px), measured on the page with `useContainerWidth` (`@tinycld/core/ui/forms/use-container-width`), not on the window: a 1600 px window shows three columns, a 1280 px window two, a 900 px window one (ledger, phase 3, measured).
- **D6 — Books opens on the dashboard at every size.** Spec §2 and question 1 of the design gate. On a phone the Lists hub is then reached from the Books sidebar in the drawer (a swipe from the left edge) and from a widget link; `help/navigating-books.md` says so. E2E helpers that started on the hub's cards go there with `showListsHub(page)` (checkpoint 2), which is the user's path.
- **D7 — widget components come in by checkpoint.** `DashboardGrid` draws the widgets of `DASHBOARD_WIDGETS`, a `Partial<Record<WidgetId, …>>` in checkpoint 2 (Invoices only) that checkpoint 3 completes to a full `Record<WidgetId, …>`. A widget id with no component draws nothing. The header's Customize button comes with edit mode in checkpoint 4; gate 2 of checkpoints 2 and 3 does not count its absence.
- **D8 — gate 2 judges the arrangement.** The reference is drawn from the fixture; the built page shows the seeded book. Gate 2 compares the card, its parts, tones, spacing and states, not the names and numbers. The states `loading`, `error`, `prefs-error`, `empty`, `empty-read-only` and `read-only` are reached on the built page with the route fakes of `tests/e2e/dashboard-helpers.ts` from a gate-2 capture step.
- **D9 — Sales "This fiscal year" columns.** One column per month of the fiscal year, future months included (a baseline mark). With no column picked, the line shows the latest month that is not after today's month.
- **D10 — the comparison line.** `change` is `null` when the earlier period has no income and no expense, or when its net profit is zero. Else the direction is `down` when this period's net profit is below the earlier one's, `up` when not; the percent is `Math.round(Math.abs(now - before) / Math.abs(before) * 100)`.
- **D11 — fixture and seed.** The fixture holds computed widget models, not records, so it is not wired into `seed.ts`; the seed already posts invoices, payments and expenses and connects bank accounts (spec §4 "Seed and fixture"). Checkpoint 1 types the fixture's two view-row lists with the generated types.
- **D12 — the full Books e2e suite.** Checkpoint 2 changes the screen every Books spec starts on. Its gate 1 runs the named set (one spec for each changed helper path, desktop and phone); the driver's CI run is the proof for the rest. The checkpoint hands back `NEEDS-RUN: full Books e2e suite` with its commit.
- **D13 — the first-run setup card shows on the dashboard too.** The Lists hub draws `SetupCard` for a Books admin whose setup is not completed (`components/ListsHub.tsx`, `showSetupCard` of `hooks/useListsHub.ts`). Books now opens on the dashboard, so that admin would not see it. The dashboard draws the same `SetupCard` under the heading on the same condition (test id `books-setup-card`, unchanged); the Lists hub keeps its card. `help/setup-wizard.md` says "at the top of the Dashboard or the Lists page". The spec does not name the card; the plan adds it so the landing change loses no entry point (checkpoint 2).
- **D14 — the accounts read is the chart's.** The Bank accounts widget and the "Waiting to deposit" line use `useAccountsQuery` (`accountsWithBalances` over every account), the read the Chart of Accounts and the account pickers hold, and filter in the pure helpers. Spec §4 names the same helper "over active Bank, Credit card and Undeposited funds accounts"; a second, filtered copy of that join would load the same rows again under another key.
- **D15 — the balances read does not move with a period.** `useDashboardBalances` reads `books_account_balances` from the earliest month any period choice can need (`earliestMonth(today, fiscalStart)`: the least of the start of the year before the last fiscal year and the start of the year before the last 12 months; at most 36 months back), so a period change computes from rows the store holds and no widget returns to its skeleton. Spec §4 says "the earliest month any of the three needs"; this is its upper bound.
- **D16 — links are real links.** `TextLink`, a bank row and a widget's create button are expo-router `Link`s (`<Link href={…} asChild>` over a `Pressable`, as `components/banking/review/ReviewRow.tsx`), with the href from `useOrgHref()`. On web each is an anchor, so e2e asserts its `href`.
- **D17 — dashboard locators name the visible screen.** The stack keeps a covered screen mounted and hidden, so every helper of `tests/e2e/dashboard-helpers.ts` scopes to `page.getByTestId('dashboard-screen').filter({ visible: true })`.
- **D18 — the e2e budget and what it leaves to unit tests and gate 3.** Twelve tests cover the page's flows; the Retry of the balances read (`useDashboardBalances`) has the same `recoverLiveQueries` form as the two reads e2e does fail (the Invoices views, the bank connections) and is checked by gate 3, not by a thirteenth test.
