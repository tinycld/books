## Deferrals
- **agreed:** gate-1 finding of checkpoint 3 (ledger, checkpoint 3): a list covered by an open record page must leave the Tab order and the accessibility tree
  **built:** web: the covered list column is `inert` (no Tab stops, not read out); native: `aria-hidden` hides it from VoiceOver and TalkBack, but an Android hardware keyboard's Tab can still move focus into the covered rows
  **reason:** missing dependency
  **blocker evidence:** React Native 0.88.1 has no View prop that stops Android's keyboard focus search in a subtree (Android `descendantFocusability`): `command grep -rlE "descendantFocusability|blocksDescendants"` over `node_modules/react-native/Libraries` and `node_modules/react-native/ReactAndroid/src/main/java/com/facebook/react/views/view` finds nothing; the same search over `tinycld/core/lib`, `core/ui`, `core/components` finds no core helper (the `inert` matches there are the editor and logger, not focus). Implementer (b) searched core and the RN View props too (`cp/cp3-impl-b.md`, b3)
  **impact:** on an Android tablet with a hardware keyboard, Tab can reach rows of the list hidden under an open vendor, customer, product or sales page; a screen reader and the web are not affected
  **unblock:** React Native (or a core native module) exposes descendant focusability on View; core then wraps it and Books passes it beside `aria-hidden` in `ListDetailLayout.tsx` — core owner
  **tracked in:** this ledger, checkpoint 3; core change request in the checkpoint 3 hand-back
  **found by:** implementer (self-declared, b3 as a declared difference, not as a deferral); reviewer B
  **checkpoint:** 3
