## Design notes
- cp 1 · reviewer A NOTE 1 · `server/vendor_refunds.go:276-280` — the header check parses `date` only on a create or a date change (declared difference 3). No user path stores an unreal day (the schema pattern holds), but `TestVendorRefundPost_RefusesACreditDatedAfterTheRefund` sets the date by raw SQL to a value the schema refuses, and no test asserts that a draft update of `date` to `2026-02-30` is refused under `date`. Suggested: add the update case; move the posting test's date by a normal draft update.
- cp 1 · reviewer A NOTE 2 · `server/vendor_refunds.go:273` — `correctedVendorRefund` runs on every draft write (declared difference 6): a saved correction draft whose original is later voided or replaced elsewhere refuses every later save with "Only a posted vendor refund can be edited."; only Delete is left (a received payment's draft stays saveable and is refused at Post). Checkpoint 4 must show such a draft as "This vendor refund cannot be edited" or show the summary refusal. Also, the inactive-vendor text wins over "A vendor refund correction keeps its vendor." for a correction draft moved to an inactive other vendor (order only; the correction's Vendor is read-only).
- cp 1 · reviewer A NOTE 3 · `server/vendor_credits.go:211` — a vendor credit correction moves only posted refunds' lines (spec §3.9); a draft refund's lines stay on the voided original, and its Post is then refused with "Vendor credit N is not open. Clear it to continue." (the seeded $275.00 draft is this case). An invoice correction moves draft payment lines too. For checkpoint 5's help text (the void and correction rules).
- cp 1 · reviewer A NOTE 4 · `server/vendor_credits.go:281-289` — a vendor credit correction can move the credit date after a posted refund that names it; the refund then names a later-dated credit, its cash-basis share rows fall before the credit's own rows, and a later Edit of that refund is refused at Post with "dated after the refund date". Spec silent. Human decision: refuse a correction dated after its earliest posted refund, or accept and document.
- cp 1 · reviewer A NOTE 5 · spec §4 — the audit `LINES` row's third element is written `vendor_refund` in the spec and the plan; the code's `refund` is right (the view selects the line field; `server/audit_log_test.go` pins it). The spec text needs the fix.
- cp 1 · reviewer A NOTE 6 · out-of-plan list — `review-diff.mjs` lists `pb-migrations/2100000001_*` and `2100000002_*` as out of plan although the Files block names them by glob (`2100000001_*.js`); only `tinycld/books/types.ts` is out of plan. A script defect for the helix maintainer.
- cp 1 · reviewer A NOTE 7 · `server/vendor_refunds.go:288-292` — the Refunded to check runs on a draft write only when the account changes; Post checks again (asserted). No test covers a draft update of `refunded_to` to an expense account. Suggested: add the case to `TestVendorRefund_RefundedToIsAnActiveRefundAccount`.
