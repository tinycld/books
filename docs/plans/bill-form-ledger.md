## Rebuttals
- **finding:** reviewer A, checkpoint 2, NOTE 1: "`isTooLarge` is now also true when the subtotal or the total passes `maxStoredAmount`, and `useDocumentTotals` sends the Subtotal and the tax amount through `moneyOrTooLarge(…, tooLarge)`. Before this change, a document whose lines are each inside `maxLineAmount` but whose sum is past `maxStoredAmount` showed the Subtotal as a number and the big figure as "Too large". Now the Subtotal and Tax rows also show "Too large". … it conflicts with "the invoice … behave exactly as before"." — and reviewer B, checkpoint 2, finding 17 (the same change; "accept it as a declared difference in the ledger, or keep the sales display as it was").
  **rebutted because:** the checkpoint orders the rule: Tests it must add, `tests/document-lines.test.ts` — "a total over `maxStoredAmount` reports `isTooLarge`", and `isTooLarge` is the one flag the totals rows read. The changed state is one the layer already called invalid: the big figure showed "Too large" and the server refuses the save (`sales_documents.go:610`, "TooLarge || Total > max || Subtotal > max"), so a Subtotal printed as a figure Books cannot store was the inconsistent part (memory p1-ledger: "Client forms must stay under it and show the server's refusal"). Reaching it takes ten lines at the per-line maximum; every invoice, sales receipt and estimate unit and e2e test stays green unchanged. Recorded as an intended change for the human.
- **finding:** reviewer B, checkpoint 3, DEFERRAL 4: "Wide action bar Delete draft. Agreed: spec §3.6, "wide — Cancel, Delete draft (saved drafts), Save draft, Post & new, Post". Exists: Delete draft is in More at every width (`DocumentActionBar` `useMoreItems`; e2e l.441 clicks `bill-more` on desktop)." (also the critic's "For gate 3" item)
  **rebutted because:** the same spec sentence ends "As the invoice's bar without Download PDF", the layer's bar (`components/documents/DocumentActionBar.tsx` `useMoreItems`: "Post & new on a phone, Delete draft …, then the caller's rows") holds Delete draft in More at every width for every kind, and the human-approved reference `docs/plans/bill-form-reference/draft-1280-light.png` shows Cancel, Save draft, Post, Post & new, More. The spec's own list contradicts its reference; the build follows the reference and the layer. Shown to the human under Design notes.
- **finding:** reviewer B, checkpoint 3, DEFERRAL 5: "Settings read in `BILL_DATA.formStart`. Agreed (Do 5): the form start from `useBooksSettings` "with its own `isError` and recovery". Exists: `useBillFormStart` returns `isError: false, recovery: NO_RECOVERY` and relies on the screen's own settings read (`useDocumentScreen.ts:63,107,203`)."
  **rebutted because:** the spec's requirement is §3.9 "load error with Retry for each failing read (merged recoveries, the settings read included)", and it holds: the screen's settings read is in the merged recoveries (`useDocumentScreen.ts:63,107,203`) and `tests/document-screen-state.test.ts` ("Retry recovers … the settings read", l.416) pins it. A second read of the same row with its own recovery would add a duplicate query and nothing a user can see.
