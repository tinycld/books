# Bill form — checkpoint plan

Package: `books` (dir `/Users/nas/tmp/tinycld/books/books`). Feature: `bill-form`. Spec: `docs/specs/bill-form-design.md` (design gate approved 2026-11-13). Unit: p3-bill, unattended, review mode C. Step branch `books/p3-bill` in the package (from books main 3fdb32c, which has the merged p2-estimate layer). Core is `/Users/nas/tmp/tinycld/books/tinycld` on main; **no checkpoint 0, no core change**: a checkpoint that finds it needs one stops and reports it. Paths are relative to the package root. Source lives in `tinycld/books/`. Package files and screens import each other relatively (`../lib/x`), never with `~/tinycld/books/...` (the export fails otherwise). Every screen works on web and native. No raw hex: semantic Tailwind tokens or `useThemeColor`. No `console.*`. Data goes through pbtsdb (`useStore`, `useLiveQuery` with `{ query, queryKey }`, `materialize()`), writes through `useMutation` from `@tinycld/core/lib/mutations`. Row types derive from the query result or the generated type. No `useState` + `useEffect` sync. Forms are zod through the forms engine and `zodResolver`. Action buttons with a key are `ShortcutButton`s with `scopeOwner` from the screen's `useShortcutScope` (memory p0a1). Money math goes through the shared helpers (`lib/document-lines.ts`, `lib/money.ts`); no screen does its own arithmetic on dollars.

Reference screenshots live in `docs/plans/bill-form-reference/` as `<shot>-<width>-<scheme>.png`, from `docs/plans/bill-form-capture.json`: `new`, `new-accounts`, `new-products`, `draft`, `correction`, `correction-phone`, `errors`, `no-lines`, `delete`, `phone-more`, `posted`, `posted-phone`, `void`, `reader`, `settings`, `settings-readonly`, `loading`, `error`, `not-found`, `no-access`. `lib/bill-form-fixture.ts` holds the data they show. It builds its kind as `{ ...INVOICE_KIND, … }` and `{ ...INVOICE_DOCUMENT, doc }` and passes `DocumentActionBar`, `DocumentHeader`, `DocumentReadActions` their current props: a checkpoint that adds a required field to `SalesDocumentKind` or `DocumentKind` gives `INVOICE_KIND` / `INVOICE_DOCUMENT` that field (the spread then carries it), and no checkpoint renames a prop of those components. A checkpoint that still breaks the scratch route's tsc edits only the scratch route's lines that name the changed export (the file is git-excluded, so review-diff never lists it).

**Phase 3 stand-ins the build replaces, never copies** (ledger, phase 3): the scratch `BILL_KIND` spread from the invoice kind (→ the real `BILL_KIND` with party `vendor`, two line tables and no tax, message, email or PDF, checkpoints 2 and 3); the band drawn with core inputs and a local vendor `SearchPicker` (→ `FormRenderer` over the `books:bill` host with `VendorField`, `MailingAddressField`, `DocumentTermsField`, `DocumentDateField`, `DueDateField`, `VendorRefField`, checkpoint 3); the two hand-drawn line grids and cards (→ two core table built-ins with the purchase cells, checkpoint 3); the hand-drawn totals rows (→ `DocumentTotalsPanel` with per-table subtotals, checkpoint 2); the read mocks (→ `DocumentReadView` with `BillReadDetails` and `PurchaseReadLines`, checkpoint 3); the local Settings card (→ the real `SettingsShell` section `purchases`, checkpoint 5).
