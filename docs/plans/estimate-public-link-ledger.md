- **finding:** reviewer B, checkpoint 3, DEFERRAL 1: "Brief Do 4 says `PublicEstimateReady` passes `response.refusal` as the card's `refusal`. The code passes `''` while the outcome is `decide` (`PublicEstimateReady.tsx:976`, declared difference 4). Agreed: the refusal box above the outcome. Built: the box only when the outcome is not `decide`. While the outcome is `decide`, the open step's summary shows the text instead. Small, but it differs from the brief."
  **rebutted because:** nothing agreed is missing; the text is drawn once, where the spec puts it. Spec §3.3: "A refusal from the server … shows its text in core `FormErrorSummary` above the step's buttons". The plan decision for the card box is about a new outcome: "the refusal box (`estimate-public-refusal`) stays visible above the new outcome's text until the page reloads". While the outcome is still `decide` there is no new outcome text, and the open step already shows the refusal; passing it to the card too would draw the same sentence twice.
- **finding:** reviewer B, checkpoint 3, DEFERRAL 2: "Spec §3.5 and the checkpoint say: "A writer with the estimate form open who saves after the customer responded gets the existing revision conflict". The built code gives the conflict only when the form already had an unsaved change when the row moved … A writer who opens the form, sees the realtime update and then edits gets no conflict. That is correct, because nothing is overwritten, but it is narrower than the spec text. … Ask the human to sign off on the spec wording."
  **rebutted because:** the spec asks for the existing mechanism, against an overwrite: §3.5 "gets the existing revision conflict (`ConflictNotice`), not a silent overwrite", and §8 "No change to the estimate form's status rules". The existing mechanism (`hooks/useDocumentSave.ts`: "The form follows the row while it has no unsaved change, so the baseline follows it too") lets a clean form take the customer's status, so its save overwrites nothing; only a form with an unsaved change could overwrite, and that one gets the conflict (e2e `accept`). Human: please confirm the wording at the eval gate.
