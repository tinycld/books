- **Where the server checks run.** `uploadRecordWithFile` keeps only a response's top-level `message`, so every refusal a file create can meet is a top-level `refuse(...)`:

  The create rule pins the stamped fields over REST. PocketBase checks the create rule before the request hook runs (third_party/pocketbase/apis/record_crud.go `recordCreate`), so a client that sends `status` is refused with "Failed to create record." before any Books check.

   ```ts
   // The key and insert-input type parameters follow accountsWithBalances (lib/accounts-query.ts):
   // a pbtsdb collection omits server-stamped fields on insert, a plain collection does not.
   export function bankConnectionsQuery<
       CK extends string | number, AK extends string | number,
       BK extends string | number, FK extends string | number,
       CI extends object, AI extends object, BI extends object, FI extends object,
   >(
       connections: Collection<BooksBankConnections, CK, UtilsRecord, never, CI>,
       accounts: Collection<BooksAccounts, AK, UtilsRecord, never, AI>,
       balances: Collection<BooksAccountBalances, BK, UtilsRecord, never, BI>,
       files: Collection<BooksBankFiles, FK, UtilsRecord, never, FI>
   ) {
       return (query: InitialQueryBuilder) => {
           const totals = query.from({ balance: balances }).groupBy(({ balance }) => balance.account)
               .select(({ balance }) => ({ account: balance.account, debit_total: sum(balance.debit_total), credit_total: sum(balance.credit_total) }))
           const waiting = query.from({ file: files }).where(({ file }) => eq(file.status, 'uploaded'))
               .groupBy(({ file }) => file.connection)
               .select(({ file }) => ({ connection: file.connection, count: count(file.id), last: max(file.created) }))
           return query.from({ connection: connections })
               .innerJoin({ account: accounts }, ({ connection, account }) => eq(connection.account, account.id))
               .leftJoin({ total: totals }, ({ account, total }) => eq(account.id, total.account))
               .leftJoin({ files: waiting }, ({ connection, files }) => eq(connection.id, files.connection))
               .orderBy(({ account }) => account.number)
               .orderBy(({ account }) => account.name)
               .select(({ connection, account, total, files }) => ({
                   id: connection.id, account: connection.account, accountName: account.name,
                   accountNumber: account.number, accountType: account.type,
                   institution: connection.institution, accountMask: connection.account_mask,
                   debitTotal: coalesce(total?.debit_total, 0), creditTotal: coalesce(total?.credit_total, 0),
                   waitingCount: coalesce(files?.count, 0), lastUploadAt: files?.last,
               }))
       }
   }
   ```
   with the comment of `accountsWithBalances` (why the aggregates cannot duplicate a row) and why it is a join (the strip sorts by the account's number). If TanStack DB 0.12 refuses an expression above, fix it at the expression (for example `coalesce` around `max`), keeping one query.

**Decisions (keys):**
- **Scopes.** The page registers N and U in a `list` scope from its own `useShortcutScope('list')` in `useBankingShortcuts` (called by `BankingScreenView`, the component that also renders the page). Every core dialog and sheet renders `LayerEscape`, which pushes a `modal` scope while it is open, so the page keys do nothing while a dialog is open. A dialog's ⌘↵ lives in `DialogSubmitKey`, rendered inside the dialog's body: it calls `useShortcutScope('modal')` and registers with that owner, so its scope sits above the dialog's `LayerEscape` scope (React runs the layer's effects before those of the body that follows it) and is popped when the dialog closes. Each Books dialog renders only while open (it returns null otherwise), so no `DialogSubmitKey` outlives its dialog, also on a phone where the sheet would slide out. Core's layer stack alone takes Escape while a layer is open (core #436), so Esc cancels every dialog with no Books code.
- **Tracing each key from every element that can hold focus (lesson 21).** ⌘↵ in a dialog: from a text field (Bank name, Last 4) core reads it in the capture phase for scoped shortcuts (`allowInInputs`) → submits; from the autofocused Account trigger or a footer button, a modified key is read in the capture phase → submits; with the Account menu open, core sends every key to the bubble phase and the focused menu row stops Enter → nothing happens (the user closes the menu first). N and U on the page: plain letters take the bubble phase; a focused strip card, the More trigger, Choose file or Remove (Pressables) stop only Enter and Space, so the letter reaches the page → runs; the page has no text field; with the More menu open (a menu pushes no scope) the letter could reach the page from a focused menu row, so `bankingKeyAvailable` returns false while `isPanelMenuOpen` (the store) is true; the ⇧? overlay pushes its own `modal` scope → the page keys do nothing; Escape closes the overlay.
- **Offered keys** (`offeredBankingKeys`): `connect` when `canWrite && !isWriteBlocked` and the state is `intro` or `ready`; `chooseFile` when `canWrite && !isWriteBlocked`, the state is `ready` and a connection is selected. `bankingShortcuts` builds a shortcut only for an offered key (core's ⇧? list does not read `when`; memory p3-transfer), and `useBankingShortcuts` memoises on the joined offered keys, so the keys re-register only when what is offered changes. `when` (`bankingKeyAvailable`) still reads the state at press time: false while the More menu is open, and for `chooseFile` while an upload runs.
- **U opens the file input inside the key event.** U's `run` calls `upload.pick()`, which calls core `pickFiles` synchronously (checkpoint 6, Do 2), so the browser's file dialog opens inside the keydown's user activation; on native it opens the document picker.
- **Autofocus.** Connect: `SelectInput autoFocus={isWide}` (core focuses once at mount, web only). Edit: Bank name `TextInput autoFocus={isWide}` (on native too when wide, a tablet: the spec ties it to "wide"; on a phone nothing is focused, so the keyboard does not cover the sheet). The dialogs mount only when opened, so the focus lands when the dialog opens.
- **Descriptions and ids.** Group `Banking`. Page: `Connect account` (N), `Choose file` (U); ids `books.banking.page.<instance>.<action>`. Dialogs: `Connect` / `Save` / `Remove file` / `Disconnect`; ids `books.banking.dialog.<instance>.submit`. `<instance>` is `useId()`.
